## Prerequisites

| Dependency | Version | Purpose |
|---|---|---|
| Go | 1.25.14+ | Build the binaries (`go.mod` requires 1.25.14) |
| Podman | 4.0+ | Run the stack and the containerized tests |
| PostgreSQL | 17 | Primary data store (runs in the pod) |
| golang-migrate | latest | `make migrate-up`/`migrate-down` and `make test-integration` (the pod migrates itself) |
| golangci-lint | v2 | `make lint` only |

## Build from source

```bash
git clone https://github.com/infrashift/chit.git
cd chit
make build
```

This produces `bin/chitd` — the main server binary.

## Build the MCP server

```bash
make build-mcp
```

This produces `bin/chit-mcp` — an MCP server for AI agent integration.

## Build the other binaries

```bash
make build-reconcile   # bin/chit-reconcile — pushes CUE roles/actors into Keto
make build-claude      # bin/chit-claude — headless Claude Code bridge
make build-all         # everything at once
```

See [Headless Claude Code](/chit/deployment/headless-claude/) for setting up the
bridge.

## Build the container image

```bash
make kube-build
```

This builds `localhost/chit:latest` from `deploy/Containerfile`, containing
`chitd` and `chit-reconcile` and the CUE definitions at `/etc/chit/auth`.
`make kube-up` runs it first.

## Run the tests

```bash
make test               # unit tests, with -race
make test-integration   # store and pub/sub tests against a throwaway PostgreSQL
make lint               # golangci-lint, including integration- and e2e-tagged files
make vuln               # govulncheck
make check-deps         # dependency boundaries between the binaries
```

`make test-integration` starts a disposable `postgres:17-alpine` container in
Podman on port `55432` (override with `ITEST_PORT`), runs every migration up,
all the way down and up again, runs the `integration`-tagged tests in
`internal/store/sqlstore` and `internal/pubsub`, and removes the container. The
suite truncates every table, so never point it at a database you care about.

### In a container

The test Containerfile builds a UBI9-based image with the Go toolchain and runs
the unit tests inside it. No PostgreSQL or external services are required; the
unit tests use in-memory fakes.

```bash
make test-container
```

This builds the `chit-test:latest` image (compile-gating at build time) and then
runs `go test -race -count=1 -v ./...` inside it.

To run a specific test or package, override the default `CMD`:

```bash
podman run --rm chit-test:latest go test -run TestSpecific ./internal/model/...
```

To build with a different Go version:

```bash
podman build --build-arg GO_VERSION=1.25.14 \
  -t chit-test:latest -f Containerfiles/Containerfile.test .
```

## Verify the build

chitd takes no command-line flags; running it starts the server, which exits at
once without `CHIT_DATABASE_URL`. To check the build, list the binaries:

```bash
ls bin/
```

To run chitd, see [Quick Start](/chit/getting-started/quick-start/).
