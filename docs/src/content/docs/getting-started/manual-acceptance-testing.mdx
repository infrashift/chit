title: Manual Acceptance Testing
description: Spin up a self-contained UAT environment with pre-seeded users for manual API testing.
---

The UAT environment runs chitd and PostgreSQL in a Podman pod with five
pre-seeded users. No Ory stack is needed — requests authenticate via the
`X-User-Id` header with fixed Kratos IDs.

## Prerequisites

| Dependency | Version | Purpose |
|---|---|---|
| Podman | 4.0+ | Run the UAT pod |

No Go toolchain needed on the host — everything runs inside the container.

## Start the environment

```bash
make uat-up
```

This builds the E2E container image, creates a Podman pod, starts PostgreSQL,
runs migrations, seeds test data, and starts the chitd server on port 8065.

To use a different host port:

```bash
UAT_PORT=9065 make uat-up
```

Watch the server logs to confirm startup:

```bash
podman logs -f chit-uat-chitd
```

## Verify

```bash
curl http://localhost:8065/api/v1/system/ping
```

Expected response:

```json
{"status": "OK"}
```

## Users

All requests require the `X-User-Id` header set to the user's Kratos ID.
Alice has the `system_admin` role; all others are `system_user`.

| Username | Display Name   | X-User-Id header                           |
|----------|----------------|---------------------------------------------|
| alice    | Alice Anderson | `a11ce000-0000-4000-a000-000000000001`      |
| bob      | Bob Baker      | `b0b00000-0000-4000-a000-000000000002`      |
| chad     | Chad Cooper    | `c4ad0000-0000-4000-a000-000000000003`      |
| diana    | Diana Drake    | `d1a4a000-0000-4000-a000-000000000004`      |
| eve      | Eve Ellis      | `e0e00000-0000-4000-a000-000000000005`      |

## Curl examples

For convenience, set a shell variable for Alice's header:

```bash
ALICE="X-User-Id: a11ce000-0000-4000-a000-000000000001"
BOB="X-User-Id: b0b00000-0000-4000-a000-000000000002"
```

### Who am I

```bash
curl -H "$ALICE" http://localhost:8065/api/v1/users/me
```

### Post a message

Replace `CHANNEL_ID` with the Town Square channel ID from the seed output.

```bash
curl -X POST -H "$ALICE" -H 'Content-Type: application/json' \
  -d '{"channel_id":"CHANNEL_ID","message":"Hello from UAT!"}' \
  http://localhost:8065/api/v1/posts
```

### Read channel posts

```bash
curl -H "$ALICE" http://localhost:8065/api/v1/channels/CHANNEL_ID/posts
```

### Reply to a thread

Use the `root_id` field with the ID of the post you're replying to:

```bash
curl -X POST -H "$BOB" -H 'Content-Type: application/json' \
  -d '{"channel_id":"CHANNEL_ID","root_id":"POST_ID","message":"Threaded reply!"}' \
  http://localhost:8065/api/v1/posts
```

### Search users

```bash
curl -H "$ALICE" 'http://localhost:8065/api/v1/users?term=bob'
```

### Create a DM channel

Pass an array of exactly two user IDs:

```bash
curl -X POST -H "$ALICE" -H 'Content-Type: application/json' \
  -d '["ALICE_USER_ID","BOB_USER_ID"]' \
  http://localhost:8065/api/v1/channels/direct
```

### List teams

```bash
curl -H "$ALICE" http://localhost:8065/api/v1/teams
```

### List channels in a team

```bash
curl -H "$ALICE" http://localhost:8065/api/v1/teams/TEAM_ID/channels
```

## How auth bypass works

In production, Ory Oathkeeper authenticates requests and sets the
`X-User-Id` header before forwarding to chitd. The `AuthExtract` middleware
reads this header and calls `ProvisionUser`, which looks up the user by
Kratos ID in the database.

In the UAT environment, there is no Oathkeeper proxy. Requests go directly to
chitd. Since the seed program pre-creates users with known Kratos IDs in the
database, `ProvisionUser` finds them on the first lookup — Kratos is never
called. This means you can authenticate as any seeded user by setting the
`X-User-Id` header directly.

## Tear down

```bash
make uat-down
```

This removes the Podman pod and all its containers.
