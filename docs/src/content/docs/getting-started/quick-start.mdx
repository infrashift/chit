This guide walks you through starting the complete Chit stack using Podman
Kube, running migrations, and verifying the server.

## 1. Start the infrastructure pod

```bash
make kube-up
```

This runs `podman kube play --network host deploy/chit.kube.yml`, which starts:

- PostgreSQL 17
- Ory Kratos (identity)
- Ory Oathkeeper (auth proxy)
- Ory Keto (authorization)
- ZincSearch (full-text search)

Kratos, Keto, and Chit schema migrations run automatically via init/migrate
containers — no separate migration step is needed on first start.

:::tip
If you later pull new Chit migration files, apply them to the running pod
with `make kube-migrate` — it runs a one-shot migrate container against the
pod's PostgreSQL, no restart required.
:::

## 2. Configure the environment

```bash
cp .env.example .env
```

The defaults in `.env.example` are configured for the local Podman Kube pod.
No changes are needed for local development.

## 3. Build and run the server

```bash
make run
```

The server starts on `:8065` by default.

## 4. Verify

```bash
curl http://localhost:8065/api/v1/system/ping
```

Expected response:

```json
{"status": "OK"}
```

## 5. Register a user

Create an identity via Kratos:

```bash
curl -s -X POST http://localhost:4433/self-service/registration?flow=api \
  -H 'Content-Type: application/json' \
  -d '{
    "method": "password",
    "traits": {
      "email": "alice@example.com",
      "username": "alice",
      "name": "Alice"
    },
    "password": "securepassword123!"
  }'
```

On first authenticated request through Oathkeeper, Chit auto-provisions a
local user record from the Kratos identity.
