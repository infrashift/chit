---
title: Podman Kube
description: Deploying the Chit infrastructure stack with Podman Kube.
---

Chit's infrastructure runs as a single Podman Kube pod defined in
`deploy/chit.kube.yml`. This deploys all required services with a single
command — no Docker Compose required.

## Pod Contents

The pod runs 6 containers alongside the Chit server:

| Container | Image | Port(s) | Purpose |
|---|---|---|---|
| **postgres** | `postgres:17-alpine` | 5432 | Primary data store |
| **kratos** | `oryd/kratos:v1.3` | 4433, 4434 | Identity management |
| **oathkeeper** | `oryd/oathkeeper:v0.40` | 4455, 4456 | Authentication proxy |
| **keto** | `oryd/keto:v0.12` | 4466, 4467 | Authorization (ReBAC) |
| **vault** | `vault:1.17` | 8200 | Encryption (Transit Engine) |
| **zincsearch** | `zincsearch:latest` | 4080 | Full-text search indexing |

## ConfigMaps

The Kube manifest includes ConfigMaps for service configuration:

| ConfigMap | Contents |
|---|---|
| `chit-postgres-init` | SQL script to create `kratos` and `keto` databases |
| `chit-kratos-config` | Kratos server config + identity schema |
| `chit-oathkeeper-config` | Oathkeeper access rules and server config |
| `chit-keto-config` | Keto namespace and relationship definitions |

## Persistent Volumes

| PVC | Mount | Purpose |
|---|---|---|
| `chit-pgdata` | `/var/lib/postgresql/data` | PostgreSQL data directory |
| `chit-zincdata` | `/data` | ZincSearch index data |

## Networking

The pod runs with `--network host`, so all containers share the host network
namespace. This simplifies container-to-container communication — each service
is reachable at `localhost` on its configured port.

## Makefile Targets

| Target | Command | Description |
|---|---|---|
| `make kube-up` | `podman kube play --network host deploy/chit.kube.yml` | Start the pod |
| `make kube-down` | `podman kube down deploy/chit.kube.yml` | Stop and remove the pod |
| `make kube-migrate` | Runs Kratos and Keto migration containers | Apply Ory schema migrations |
| `make migrate-up` | `migrate -database ... -path migrations up` | Apply Chit schema migrations |
| `make migrate-down` | `migrate -database ... -path migrations down` | Roll back Chit migrations |

## Containerfile

The server image is built from `deploy/Containerfile`:

```bash
podman build -t chit:latest -f deploy/Containerfile .
```

The Containerfile uses a multi-stage build: Go compilation in a builder stage,
then copies the binary into a minimal UBI-based runtime image.

## Startup Order

1. `make kube-up` — start all infrastructure containers
2. `make kube-migrate` — run Ory schema migrations (Kratos + Keto)
3. `make migrate-up` — run Chit application schema migrations
4. `make run` — build and start the Chit server
